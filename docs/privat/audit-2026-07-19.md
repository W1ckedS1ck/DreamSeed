## 🔴 CRITICAL

### 1. SSH доступ будет заблокирован

**Файл:** `ansible-roles/security/templates/sshd-hardening.conf.j2:5`

```
AuthorizedKeysCommand none
```

`AuthorizedKeysCommand` ожидает путь к файлу, а не `none`. Если `sshd -t` пропустит (в некоторых OpenSSH парсер слишком либеральный) — все SSH ключи перестанут работать.

### 2. Redis без пароля **[WONTFIX]**

**Файлы:** `group_vars/all.yml:27`, `ansible-roles/redis/templates/redis.conf.j2`
`REDIS_PASSWORD` не задаётся нигде. **Решение:** Redis на `bind 127.0.0.1`, односерверная архитектура. Пароль бесполезен против локального атакующего. Добавлены комментарии в `group_vars/all.yml` и `redis.conf.j2`.

### 3. PHP сессии игнорируют Redis auth

**Файл:** `ansible-roles/php/templates/www.conf.j2:17-20`

```ini
php_value[session.save_path] = "tcp://127.0.0.1:6379"
```

В `www.conf` нет `?auth={{ redis_password }}`. `www.conf` переопределяет `php.ini`, поэтому `php.ini` с авторизацией игнорируется. Redis auth к PHP сессиям никогда не применяется.

### 4. Cloudflare IP updater — несуществующий файл

**Файл:** `ansible-roles/nginx/tasks/main.yml:76-86`
Скрипт `{{ scripts_dir }}/update_cloudflare_ips.sh` не существует в репозитории. `failed_when: false` молча глотает ошибку. Cloudflare IP ranges не обновляются — новые IP не получают реальный IP посетителя.

### 5. Grafana fallback никогда не сработает

**Файл:** `ansible-roles/grafana/tasks/main.yml`

```yaml
failed_when: false
register: grafana_install_result
- when: grafana_install_result is failed  # НИКОГДА
```

`failed_when: false` говорит Ansible считать задачу успешной всегда. Если пакет `grafana=13.1.0` отсутствует в репозитории — Grafana не установится, деплой пройдёт, следующие задачи упадут.

### 6. Certbot webroot (HTTP-01) отсутствует

**Файл:** `ansible-roles/ssl/tasks/main.yml`
Документация обещает: restore → DNS-Cloudflare → **webroot** → self-signed. Реализация: DNS-Cloudflare → **сразу self-signed**. Webroot шаг пропущен.

### 7. DB_PREFIX дефолт `db_` вместо `modx_`

**Файл:** `ansible-roles/backup/templates/server.env.j2:17-18`

```bash
DB_PREFIX="{{ lookup('env', 'DB_PREFIX') | default('db_', true) }}"
MODX_TABLE_PREFIX="{{ db_prefix }}"  # group_vars = 'modx_'
```

Telegram-бот использует `DB_PREFIX` → backup скрипты ищут таблицы с префиксом `db_` вместо реального `modx_`.

### 8. Restore threshold off-by-one

**Файл:** `ansible-roles/restore/tasks/main.yml:67-70`

```yaml
restore_db_needs_restore: "{{ (restore_db_tables.stdout | default('0') | int) < 2 }}"
```

`SHOW TABLES` выдаёт header + N таблиц. При 1 таблице `wc -l` = 2 → `2 < 2` = false → restore пропускается.

### 9. env label mismatch — алерты не работают

**Файл:** `ansible-roles/monitoring/templates/vmagent.service.j2:15`

```
-remoteWrite.label=env={{ domain }}
```

Алерты в Grafana используют `{{ deploy_env }}` (`dev-aws`, `prod`). vmagent шлёт `env=dreamseed.online`. Алерты не могут матчить метрики.

### 10. Shell injection в GitHub Action

**Файл:** `.github/actions/setup-ansible/action.yml:29`

```yaml
ansible-galaxy collection install ${{ inputs.collections }}
```

`inputs.collections` передаётся в shell. Если collection содержит shell metachar — RCE в CI.

### 11. RESTORE_ALL.sh — fallback на gdrive мёртв

**Файл:** `scripts/RESTORE_ALL.sh:343-354`

```bash
rclone lsf ... | tail -3 || rclone lsf gdrive:...
```

Exit code пайпа = exit code `tail -3` (всегда 0). `||` никогда не выполняется.

### 12. audit_deep.sh — .env не загружен

**Файл:** `scripts/audit_deep.sh:11-12`
`load_env` не вызывается. Все переменные пустые, audit работает наслепую.

### 13. telegram_bot.py — незашифрованный remote

**Файл:** `scripts/telegram_bot.py:34`

```python
RCLONE_REMOTE = 'gdrive'  # должно быть 'gdrive-crypt'
```

Все shell-скрипты используют `gdrive-crypt` (шифрование на лету). Бот читает файлы без расшифровки.

### 14. Deploy confirm не различает prod-aws и prod-hetz

**Файл:** `.github/workflows/deploy.yml:262-272`

```yaml
if [[ "${{ inputs.confirm }}" != "destroy prod" ]]
```

`prod-hetz` тоже требует `destroy prod`. Пользователь думает про AWS, а удаляет Hetzner (или наоборот).

### 15. DEPLOY_ENV не экспортируется deploy.sh

**Файл:** `group_vars/all.yml:97`

```yaml
deploy_env: "{{ lookup('env', 'DEPLOY_ENV') | mandatory(...) }}"
```

`deploy.sh` не экспортирует `DEPLOY_ENV`. Передаётся только через extra-vars JSON. При сбое extra-vars — Ansible падает.
