## HIGH

### H1. Terraform не читает ansible-vault

**Файл:** `terraform/grafana/terraform.tfvars`
**Суть:** Файл зашифрован ansible-vault, но Terraform ожидает plaintext HCL. Без ручной расшифровки `terraform apply` упадёт.

**Рекомендация:** Перейти на `TF_VAR_*` переменные окружения (уже используются в `deploy.sh`, но не в `deploy.yml`).

### H2. Дублирование логики deploy.sh в CI

**Файлы:** `.github/workflows/deploy.yml`, `backup-test.yml`
**Суть:** ~250 строк в каждом из этих файлов дублируют логику из `deploy.sh`: сборка `secrets/.env`, запись SSH-ключей, ожидание cloud-init, подтверждение destroy.

**Рекомендация:** Вынести в `.github/actions/` composite actions.

### H3. `j2lint --ignore` флаги — FALSE POSITIVE в аудите

**Файл:** `scripts/lint.sh:93`
**Суть:** Аудит ошибочно утверждал, что `--ignore` требует comma-separated. На самом деле j2lint принимает аргументы через пробел: `--ignore rule1 rule2 rule3`. Исходный код был правильным.

**Ложное исправление (06.06.2026):** было изменено на comma-separated, что сломало CI. **Откачено обратно.**

### H4. Template injection в check_site.sh.j2

**Файл:** `ansible-roles/monitoring/templates/check_site.sh.j2` (строки 51, 90)
**Суть:** Переменные `{{ db_name }}` и `{{ db_prefix }}` вставляются в shell SQL-запросы без экранирования. Используется только `replace("'", "''")`, но не экранируются `$()`, `` ` ``, `;`, `\`.

**Рекомендация:** Использовать `| quote` фильтр Jinja2.

### H5. Grafana Cloud — дашборды привязаны к одному datasource

**Файл:** `terraform/grafana/main.tf:32`
**Суть:** Имя datasource `grafanacloud-prom` hardcoded. Если в Grafana Cloud org datasource называется иначе, все 4 дашборда покажут "Data source not found".

### H6. Нет предварительного backup при rollback

**Файл:** `.github/workflows/rollback.yml`
**Суть:** При откате не создаётся backup текущего состояния. Если последний backup битый или несовместимый, данные безвозвратно теряются.

### H7. Terraform drift-detection — exit code 1 игнорируется

**Файл:** `.github/workflows/drift-detection.yml:56`
**Суть:** `terraform plan -detailed-exitcode` может вернуть 1 (ошибка) или 2 (drift). Workflow проверяет только код 2. При ошибке плана дрифт детектируется как "no drift".

### H8. GITHUB_TOKEN с избыточными правами

**Файлы:** `ci.yml`, `deploy.yml`
**Суть:** В `deploy.yml` используется `pull-requests: write` без необходимости. В `ci.yml` permissions не заданы (по умолчанию `contents: write`).

## MEDIUM

### M1. Telegram MarkdownV2 escaping сломан

**Файлы:** `deploy.yml`, `drift-detection.yml`
**Суть:** MarkdownV2 требует экранирования `_*[]()~>#+-=|{}.!`. Сообщения с URL, IP-адресами, датами вызывают ошибки Telegram API `400 Bad Request`.

### M2. `escape_md2` — Bash и Python реализации различаются

**Файлы:** `scripts/common_functions.sh:103`, `scripts/telegram_bot.py:36-39`
**Суть:** Python-версия экранирует `\`, Bash-версия — нет.

### M3. Нет фильтрации имён переменных в `load_env` ⚠️ FIXED

**Файл:** `scripts/common_functions.sh:27-30`
**Суть:** `load_env` экспортирует все `KEY=VALUE` без фильтрации. `.env` с `PATH=/malicious` или `LD_PRELOAD=/evil.so` — code execution.

**Исправление (06.06.2026):** Добавлен блеклист `PATH|LD_PRELOAD|LD_LIBRARY_PATH|IFS|BASH_ENV|SHELL|SHELLOPTS|BASHOPPS|BASH_FUNC_.*`. Эти переменные игнорируются при загрузке `.env`.

### M4. `TG_THREAD_ID = 0` обрабатывается как falsy

**Файл:** `scripts/telegram_bot.py:214`
**Суть:** `if TG_THREAD_ID:` — если thread_id = 0, условие ложно. Должно быть `if TG_THREAD_ID is not None:`.

### M5. Pre-restore snapshot в `/tmp`

**Файл:** `scripts/RESTORE_ALL.sh:363`
**Суть:** Экстренный backup перед восстановлением сохраняется в `/tmp` (tmpfs). При большом объёме tmpfs может переполниться.

**Рекомендация:** Использовать `$BACKUP_DIR`.

### M6. Grafana restart на каждое изменение дашборда ⚠️ FIXED

**Файл:** `ansible-roles/grafana/tasks/main.yml`
**Суть:** Каждое копирование dashboard JSON → `notify: Restart Grafana`. ~5-10s downtime. Grafana может перезагружать дашборды через provisioning API без рестарта.

**Исправление (06.06.2026):** Убран `notify: Restart Grafana` из трёх тасков с dashboard JSON (common, web-server-specific, remove). Config-файлы (grafana.ini, datasource, alerts, systemd) — рестарт оставлен.

### M7. Отсутствует изоляция workspace для Grafana Cloud дашбордов ⚠️ FIXED

**Файл:** `terraform/grafana/main.tf:73-75`
**Суть:** Все дашборды всех окружений попадают в одну папку "DreamSeed". Если один tenant, dev и prod дашборды перезаписывают друг друга.

**Исправление (06.06.2026):** `title = "DreamSeed (${terraform.workspace})"` — теперь папки разделены: `DreamSeed (prod)`, `DreamSeed (dev-aws)`.

### M8. Deploy в CI принудительно использует `-p` (parallel)

**Файл:** `.github/workflows/deploy.yml:156`
**Суть:** Баги, работающие только в последовательном режиме, не обнаруживаются.

### M9. `risky-shell-pipe` в restore роли

**Файл:** `ansible-roles/restore/tasks/main.yml`
**Суть:** Множество shell-тасков с пайпами без `set -o pipefail`.

### M10. `setup-terraform` composite action использует `latest`

**Файл:** `.github/actions/setup-terraform/action.yml:8`
**Суть:** Terraform version = `latest`. Новая мажорная версия может сломать пайплайн.

### M11. Grafana repo key через `wget + gpg` вместо `apt_key`

## Сильные стороны (что хорошо)

- **Модульность:** deploy.sh разбит на 5 независимых модулей в `lib/`
- **Безопасность:** gitleaks + pre-commit + Ansible Vault + `no_log: true` везде, где есть секреты
- **CI/CD:** 7 параллельных проверок, Renovate для авто-обновления зависимостей
- **Idempotentность:** большинство Ansible-ролей корректно обрабатывают повторный запуск
- **Документация:** `secrets/.env.example` с полным описанием всех переменных
- **RESTORE_ALL.sh:** снабжён предварительным snapshot, проверкой архивов, автоматическим уведомлением в Telegram
- **Production safeguards:** 3-step подтверждение для destroy prod, блокировки параллельных запусков
- **Оркестрация:** единая точка входа `deploy.sh` для двух облаков, автоматическая ротация логов, бэкап tfstate
