# Code Map

Interactive visual reference of the DreamSeed codebase — modules, relationships and end-to-end flows. A companion to the static [Architecture](../architecture.md) page.

## What is it

A self-contained HTML map of the whole repository: every node is a module (terraform, ansible roles, scripts, CI, external services), edges are typed relationships (`imports`, `calls`, `reads`, `writes`, `publishes`), and flows are ordered walkthroughs of real operations (deploy, backup, monitoring, restore, maintenance). Each edge and node carries code-level evidence (file + symbol) proving the relationship exists.

## How to use it

- **Published (main branch)**: [https://w1ckeds1ck.github.io/DreamSeed/](https://w1ckeds1ck.github.io/DreamSeed/)
- **Local**: run `python3 docs/codemap/gen_codemap.py`, then open `codemap.html` in a browser. Click any node to inspect its role, files, upstream callers, downstream deps and the flows it participates in. Click edges to see the evidence. Use the flow selector to highlight an end-to-end walkthrough.

## When it updates

- **Automatically** on any push to `main` (code, workflows, docs) — the `docs.yml` workflow regenerates the map in CI from that exact commit and republishes the site, so the published map is always current by construction.
- **Cloud deploys**: `deploy.yml` regenerates the map from the deployed checkout and includes it in the Pages artifact (the site also shows environment screenshots).
- **Manually**: `gh workflow run docs.yml --ref <branch>` to publish from any branch.

> The generated outputs are **not committed** to the repository — the map only exists as a CI/CD artifact and a local build. There is no snapshot to go stale, no freshness checks to satisfy.

## How to generate locally

The three outputs (`codemap.html`, `codemap.json`, `codemap.lock`) are machine-generated by `gen_codemap.py` and gitignored. Never hand-edit them — edit the generator instead and re-run:

```bash
python3 docs/codemap/gen_codemap.py
```

The generator:

- scans the repo at the current commit, validates every node/edge/flow and their evidence symbols;
- always rewrites all three files together;
- records `generated_at`, commit, per-module SHA256 fingerprints and tree state in `codemap.lock` for provenance.

## Who it is for

- **New contributors** — orientation: where things live and how modules talk to each other.
- **Code review** — blast-radius checks: what a change to a node/flow touches.
- **Architecture maintenance** — keeping the picture honest via the generator, not prose drift.
