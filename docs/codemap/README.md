# Code Map

Interactive visual reference of the DreamSeed codebase — modules, relationships and end-to-end flows. A companion to the static [Architecture](../architecture) page.

## What is it

A self-contained HTML map of the whole repository: every node is a module (terraform, ansible roles, scripts, CI, external services), edges are typed relationships (`imports`, `calls`, `reads`, `writes`, `publishes`), and flows are ordered walkthroughs of real operations (deploy, backup, monitoring, restore, maintenance). Each edge and node carries code-level evidence (file + symbol) proving the relationship exists.

## How to use it

- **Local**: open `codemap.html` in a browser. Click any node to inspect its role, files, upstream callers, downstream deps and the flows it participates in. Click edges to see the evidence. Use the flow selector to highlight an end-to-end walkthrough.
- **Published (main branch)**: [https://w1ckeds1ck.github.io/DreamSeed/](https://w1ckeds1ck.github.io/DreamSeed/)
- **Dev preview**: `https://htmlpreview.github.io/?https://github.com/W1ckedS1ck/DreamSeed/blob/dev/docs/codemap/codemap.html`

## When it updates

- **Automatically** on any push to `main` (code, workflows, docs) — the `docs.yml` workflow regenerates the map in CI and republishes the site, so the published map is always current with the pushed commit.
- **Cloud deploys**: `deploy.yml` includes the map in the Pages artifact, so it survives deploys (the site also shows environment screenshots).
- **Manually**: `gh workflow run docs.yml --ref <branch>` to publish from any branch.

> The published site is regenerated in CI from the latest push, so it can be newer than the committed `codemap.*` copy in the repo (that copy is a snapshot from the last manual regeneration). The workflow prints a warning in its job summary when the committed copy is stale — no build failure, no auto-commit.

## How to regenerate locally

The three outputs (`codemap.html`, `codemap.json`, `codemap.lock`) are machine-generated by `gen_codemap.py`. Never hand-edit them — edit the generator instead and re-run:

```bash
python3 docs/codemap/gen_codemap.py
```

The generator:

- scans the repo at the current commit, validates every node/edge/flow and their evidence symbols;
- always rewrites all three files together;
- records `generated_at`, commit, per-module SHA256 fingerprints and tree state in `codemap.lock`, so a stale or hand-edited map is detectable.

## Who it is for

- **New contributors** — orientation: where things live and how modules talk to each other.
- **Code review** — blast-radius checks: what a change to a node/flow touches.
- **Architecture maintenance** — keeping the picture honest via the generator, not prose drift.
