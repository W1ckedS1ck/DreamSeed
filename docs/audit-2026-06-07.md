## 3. Критические проблемы (Critical) — 0 шт

### ✅ C1 — ИСПРАВЛЕНО

**`terraform validate` для `terraform/grafana` падает из-за зашифрованного `terraform.tfvars`**

- **Файл:** `scripts/lint.sh` (`run_terraform_validate`)
- **Было:** `terraform validate` подхватывал `terraform.tfvars` (зашифрован `ansible-vault`) и падал с `Error: Invalid character`
- **Решение:** Перед `terraform validate` временно переименовываем `terraform.tfvars` в `terraform.tfvars.vaulted`, запускаем validate, затем возвращаем обратно. Безопасно, атомарно, не требует vault password.
- **Проверка:** `bash scripts/lint.sh --validate-terraform` — теперь проходит (✓ `terraform/grafana — valid`)

## 4. Средние проблемы (Medium) — 3 шт

### 🟡 M1. `backup-test.yml` дублирует логику `deploy.sh` — Technical Debt

- **Файл:** `.github/workflows/backup-test.yml`
- **Проблема:** Workflow занимает 661 строку и полностью самостоятельно:
  - Создаёт `secrets/.env`
  - Генерирует inventory
  - Запускает Terraform (hetzner)
  - Запускает 7 плейбуков по отдельности
  - Управляет DNS через Cloudflare API
- **Риск:** Дублирование кода. При изменении `deploy.sh` или структуры inventory `backup-test.yml` может отвалиться. Уже видны расхождения (например, ручной `tmp_vault.yml` вместо `VAULT_TMP` JSON из `deploy.sh`).
- **Рекомендация:**
  - Рефакторить `backup-test.yml` чтобы использовать `./deploy.sh test -n -p` с `SKIP_TERRAFORM=false` или `EXISTING_IP`
  - Либо вынести общие шаги (setup secrets, terraform init/apply, generate inventory) в composite action или reusable workflow
  - Сейчас это **технический долг**, не критичный, но требует внимания

### ✅ M2 — ИСПРАВЛЕНО

**`renovate.json` валидатор в `lint.sh` использует несуществующий npm-пакет + `renovate.json` содержит deprecated `managerFilePatterns`**

- **Файл:** `scripts/lint.sh` (строка ~117) + `renovate.json`
- **Было:**
  1. `npx --yes @renovatebot/config-validator` → `E404 Not Found`
  2. `renovate.json` использовал `managerFilePatterns` в `customManagers`, `terraform`, `pip_requirements`, `ansible-galaxy` — поле deprecated в Renovate v37+, заменено на `fileMatch`
- **Решение:**
  1. `lint.sh` — `npx --yes --package renovate -- renovate-config-validator` (синхронизировано с `ci.yml`)
  2. `renovate.json` — `replaceAll: managerFilePatterns → fileMatch` (12 occurrences)
- **Проверка:** `npx --yes --package renovate -- renovate-config-validator` → `INFO: Config validated successfully`

### 🟡 M3. `ansible.cfg` — `inject_facts_as_vars = False` может быть несовместим с некоторыми сторонними ролями

- **Файл:** `ansible/ansible.cfg`
- **Проблема:** Это **architectural decision**, не ошибка. Но в `group_vars/all.yml` присутствует:

  ```yaml
  php_version: "{{ ansible_facts.php_version | default('8.3') }}"
  ```

  Что корректно использует `ansible_facts`. Однако если в будущем добавятся сторонние роли из Galaxy, они могут полагаться на `ansible_memtotal_mb` вместо `ansible_facts['memtotal_mb']`.
- **Рекомендация:** Оставить как есть, но добавить комментарий в `ansible.cfg`:

  ```ini
  # NOTE: All custom roles use ansible_facts['var'] syntax.
  # Third-party roles may need adjustment if added.
  inject_facts_as_vars = False
  ```

## 5. Низкие проблемы / Замечания (Low) — 7 шт

### ✅ L1 — ИСПРАВЛЕНО

**`VAULT_TMP` в `deploy.sh` — misleading name**

- **Файл:** `deploy.sh`, `lib/helpers.sh`, `lib/ansible.sh`
- **Было:** Переменная называлась `VAULT_TMP`, но создавала **plain JSON** (`mktemp`, `chmod 600`), а не `ansible-vault`.
- **Решение:** Переименовано в `DEPLOY_VARS_TMP` — отражает суть (временный файл с переменными деплоя). Обновлены `cleanup()` и `_ansible_cmd()`.
- **Проверка:** `grep -r VAULT_TMP` — больше не встречается в коде (только в старой документации).

### 🟢 L2. `terraform_destroy()` в `lib/terraform.sh` — workaround для TFC exit code bug

- **Файл:** `lib/terraform.sh` (строки 75–83)
- **Проблема:** Игнорируется exit code 1 от `terraform destroy` (известный баг Terraform Cloud), затем проверяется `grep -q "Destroy complete"`. Это **корректный workaround**, но:
  - Если `terraform destroy` упадёт с другой ошибкой (например, network), но exit code 1 — скрипт не словит реальную проблему.
- **Рекомендация:** Добавить дополнительную проверку на `Failed to destroy` или `Error:` в `TF_TMP_OUT` после grep.

### 🟢 L3. `check_services.sh` — `curl -sk` для HTTPS проверки

- **Файл:** `scripts/check_services.sh` (строка 47)
- **Проблема:** `curl -sk` (silence + insecure) используется для проверки `https://$DOMAIN/`. Это **корректно для self-signed сертификатов**, но если Cloudflare origin cert валидный, `-k` не нужен.
- **Рекомендация:** Оставить как есть (self-signed fallback), но добавить комментарий:

  ```bash
  # -k required because origin may use self-signed cert behind Cloudflare proxy
  ```

### 🟢 L4. `security` role — несоответствие между комментарием и пакетом

- **Файл:** `ansible-roles/security/tasks/main.yml` (строки 161–165)
- **Проблема:** Комментарий говорит `PAM password strength checking`, устанавливается `libpam-pwquality`. В комментарии выше (строка 223 в `docs/architecture.md`) упомянут `libpam-passwdqc`. Это **не влияет на функциональность**, просто inconsistency.
- **Рекомендация:** Обновить `docs/architecture.md` или комментарий.

### 🟢 L5. `telegram_bot.py` — polling без graceful shutdown

- **Файл:** `scripts/telegram_bot.py`
- **Проблема:** Бот использует `getUpdates` polling (не webhook). При получении `SIGTERM` (systemd stop) текущий `sleep(1)` или `requests.get()` может прерваться, но нет `try/finally` для корректного завершения.
- **Риск:** Низкий. Telegram бот — stateless, повторный запуск безопасен.
- **Рекомендация:** Добавить обработчик `signal.SIGTERM` для graceful exit (не критично).

### ✅ L6 — ИСПРАВЛЕНО

**`deploy.sh` — `MAX_LOG_FILES` не валидируется**

- **Файл:** `lib/helpers.sh` (`rotate_logs()`)
- **Было:** `MAX_LOG_FILES=0` или отрицательное значение ломало `tail -n +$((max + 1))`
- **Решение:** Добавлена валидация `(( max < 1 )) && max=1` — гарантирует минимум 1 файл на ротацию.

### 🟢 L7. `drift-detection.yml` — использование DEV credentials для prod

- **Файл:** `.github/workflows/drift-detection.yml` (строки 29–31)
- **Проблема:** Комментарий объясняет, что это intentional (prod migrated from dev). Это **architectural decision**, но рискованно с точки зрения безопасности (DEV credentials имеют доступ к prod ресурсам).
- **Рекомендация:** Если drift-detection требуется, создать отдельный read-only IAM пользователь для prod drift. Не использовать DEV credentials.

## 6. Положительные находки (Best Practices)

### ✅ Безопасность

- **`.gitignore`** корректно исключает `secrets/`, `.env`, `*.pem`, `*.key`, `*.service`, `CLAUDE.md`, `AUDIT_*`
- **`audit-secrets.sh`** — pre-push scanner с проверкой tracked secrets, `.env`, `.pem`, hardcoded patterns
- **`gitleaks`** — прошёл без утечек (55.37 MB scanned, 0 leaks)
- **Ansible Vault** — `secrets/.env` может быть зашифрован, `validate_env_file()` проверяет заголовок `$ANSIBLE_VAULT` и отказывается работать с зашифрованным файлом без пароля
- **`no_log: true`** на задачах с паролями (`grafana.ini`, `grafana.env`, `server.env.j2`, `mysql .my.cnf`)
- **SSH hardening** — `MaxAuthTries 3`, `PermitRootLogin no`, `LogLevel VERBOSE`, strip EC2 Instance Connect
- **Fail2ban** — custom `modx-admin` и `grafana` filters, `jail.d/custom.conf` (Jinja2)
- **Terraform** — `disable_api_termination` для prod, `http_tokens = "required"` (IMDSv2)

### ✅ CI/CD

- **Pinned actions** — все GitHub Actions используют commit SHA (`actions/checkout@df4cb1c...`), что защищает от supply chain attacks
- **`FORCE_JAVASCRIPT_ACTIONS_TO_NODE24`** — защита от устаревшего Node.js в Actions
- **`concurrency: group`** — предотвращает параллельные deploy в одну среду
- **Prod confirmation** — deploy.sh требует `[y/N]`, destroy требует 3 шага + typing `destroy prod`, rollback требует `rollback prod`
- **`::add-mask::`** — все секреты маскируются в логах GitHub Actions

### ✅ Код-стайл

- **`set -euo pipefail`** — во всех bash-скриптах (deploy.sh, lib/*.sh, scripts/*.sh)
- **`shellcheck`** — 0 errors на всех `.sh` файлах
- **`ruff`** — 0 issues на Python
- **`ansible-lint`** — 0 failures, 0 warnings
- **`j2lint`** — 0 issues на 30+ Jinja2 templates
- **`json_escape()`** — использует Python для безопасного escaping JSON (deploy.sh → VAULT_TMP)

### ✅ Архитектура

- **Модульный `deploy.sh`** — разделён на `lib/helpers.sh`, `env.sh`, `preflight.sh`, `terraform.sh`, `ansible.sh`
- **Idempotent Ansible** — все роли используют `state: present`, `creates`, `changed_when: false`
- **Multi-cloud** — единый `deploy.sh` для AWS и Hetzner через `resolve_target()`
- **Auto-detect PHP** — `packages_common` определяет версию PHP через `apt-cache`
- **Inventory auto-generation** — `hosts-<workspace>.yml` создаётся на каждый deploy
- **tfstate backup** — автоматический backup с rotation (keep 5)

### ✅ Мониторинг и DR

- **3 уровня observability:**
  1. On-server (Grafana + VictoriaMetrics + 16 alerts)
  2. Grafana Cloud (vmagent remote write + Synthetic Monitoring)
  3. Better Stack (external HTTP monitors + heartbeats)
- **Backup pipeline:** hourly local + daily cloud + verification + interactive restore
- **`RESTORE_ALL.sh`** — rollback detection через `editedon` timestamps, emergency snapshots, health check
- **`check_services.sh`** — comprehensive post-deploy validation (7+ services, HTTP, SSL, DB, exporters)
- **`smart_backup.sh`** — hash-based skip для проекта, always dump для DB, rotation

### ✅ Документация

- **README.md** — portfolio-grade, актуальный, схемы, badges, deploy commands
- **`docs/runbook.md`** — 1285 строк, подробный incident response для каждого алерта
- **`docs/architecture.md`** — flow diagrams, secrets flow, backup pipeline, alert matrix
- **`docs/prerequisites.md`** — полный список tools, credentials, collections
- **`docs/linters.md`** — mapping tools → file types
- **Всё на английском** — соответствует требованию README (portfolio repo)
