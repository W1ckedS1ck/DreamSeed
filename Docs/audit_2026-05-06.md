## CRITICAL (исправить немедленно)

### 1. SSL: Самоподписанный сертификат
- Используется self-signed `/etc/ssl/certs/nginx-selfsigned.crt`, НЕ Let's Encrypt
- Браузеры показывают предупреждение, пользователи не доверяют сайту
- Certbot timer работает, но ни одного LE-сертификата не выпущено
- **Действие:** Настроить `certbot --nginx` для dreamseed.online

### 2. Firewall: UFW выключен, iptables пустые
- `ufw status` → inactive, iptables — ACCEPT по умолчанию, правил 0
- Сервер полагается только на AWS Security Group
- **Действие:**
  ```bash
  ufw default deny incoming
  ufw allow 22
  ufw allow 80
  ufw allow 443
  ufw enable
  ```

### 3. Grafana: Пароль "adminadmin" в конфиге
- `/etc/grafana/grafana.ini` → `admin_password = adminadmin`
- `secret_key` не установлен (значение по умолчанию CHANGE_ME)
- Grafana доступна извне через `https://dreamseed.online/grafana/`
- **Действие:** Сменить пароль, установить secret_key, ограничить доступ IP

### 4. PHP: Не захарденен
- `disable_functions` = пусто (exec, shell_exec, system — доступны)
- `open_basedir` = не задан (PHP может читать /etc/passwd и т.д.)
- `expose_php` = On (утечка версии в заголовках)
- `session.cookie_httponly` = Off (XSS может украсть сессию)
- `session.cookie_samesite` = не задан (уязвимость CSRF)
- `allow_url_fopen` = On (SSRF-вектор)
- **Действие:** Настроить в php.ini:
  ```ini
  disable_functions = exec,passthru,shell_exec,system,proc_open,popen,curl_exec,curl_multi_exec,show_source,phpinfo
  open_basedir = /var/www/html:/tmp:/var/lib/php
  expose_php = Off
  session.cookie_httponly = On
  session.cookie_samesite = Strict
  allow_url_fopen = Off
  ```

### 5. MariaDB: local_infile = ON
- Позволяет `LOAD DATA LOCAL INFILE` — вектор для чтения файлов сервера через SQL-инъекцию
- **Действие:** `SET GLOBAL local_infile=0;` + добавить в `99-optimizations.cnf`

### 6. Пароли-плейсхолдеры "StrongPasswordHere"
- MODX config (`config.inc.php`) → `$database_password = 'StrongPasswordHere'`
- `.my.cnf` → `password=StrongPasswordHere`
- MariaDB exporter config → `password=StrongPasswordHere`
- `modx_user` и `monitoring` пользователи БД имеют одинаковый хэш пароля
- **Действие:** Сменить на уникальные криптостойкие пароли

### 7. SSH: Не ограничены алгоритмы
- Доступны слабые: `3des-cbc`, `diffie-hellman-group1-sha1`, `hmac-md5`, `hmac-sha1`
- **Действие:** Добавить в sshd_config:
  ```
  Ciphers chacha20-poly1305@openssh.com,aes256-gcm@openssh.com,aes128-gcm@openssh.com,aes256-ctr,aes128-ctr
  MACs hmac-sha2-512-etm@openssh.com,hmac-sha2-256-etm@openssh.com
  KexAlgorithms curve25519-sha256,curve25519-sha256@libssh.org,diffie-hellman-group16-sha512,diffie-hellman-group18-sha512
  ```

- С weak-паролем + открытым доступом = гарантированный взлом
- **Действие:** `allow YOUR_IP; deny all;` в location /grafana

### 10. Нет File Integrity Monitoring / IDS

- Невозможно обнаружить несанкционированные изменения файлов
- **Действие:** `apt install aide && aideinit`

### 11. Нет auditd
- Системные события не логируются на уровне ядра
- Невозможно отследить кто и когда обращался к критичным файлам
- **Действие:** `apt install auditd && configure rules`

### 12. VictoriaMetrics: retention = 1 месяц

### 13. Бэкап проекта: только 1 копия (с 3 мая)
- Hash-based skip = если код не менялся, бэкап не создаётся
- Для production нужен ежедневный полный бэкап независимо от изменений
- **Действие:** Убрать hash-skip или добавить обязательный ежедневный

### 14. Rclone: OAuth-токен Google Drive в открытом виде
- `/home/ubuntu/.config/rclone/rclone.conf` содержит access_token и refresh_token
- Файл читается пользователем ubuntu
- **Действие:** Ограничить права на 600, рассмотреть service account

### 15. EC2 Instance Connect
- `AuthorizedKeysCommand /usr/share/ec2-instance-connect/eic_run_authorized_keys`
